1. **Alta** — Token y `chat_id` van en argv de `curl` (`ps`/`/proc`) y `curl -sS` puede volcar la URL a stderr: rompe “nunca imprime token ni chat ids”.
2. **Alta** — `set -a; source "$TG_ENV"` ejecuta bash (RCE) y exporta todo; un `.env` con `PATH`/`LD_PRELOAD`/`BASH_ENV` secuestra `curl`.
3. **Alta** — `TG_API_HOST`/`TG_SCHEME` sin validar: token a host atacante (`host@evil`, path injection) o en claro (`http`).
4. **Alta** — `parse_mode=HTML` sin escape: `&`, `<`, `>` en el digest fallan el send (`can't parse entities`) o inyectan markup.
5. **Alta** — “NUNCA a Wide” no está en código: no hay allowlist/denylist; un `.env` mal cargado manda el digest al chat equivocado.
6. **Media** — `grep '"ok":…true'` no parsea JSON: un body de error/proxy que contenga esa cadena cuenta como éxito.
7. **Media** — Sin `--connect-timeout`/`--max-time`: `curl` cuelga el cron; si el POST ya salió y el hang es en la respuesta, un reintento duplica.
8. **Media** — Fallo parcial + “reenviar completo”: el chat que sí llegó recibe el digest otra vez; no hay idempotencia ni `message_id` por chat para no reenviar.
9. **Media** — `${#MSG}` en bash ≠ límite de Telegram (UTF-16/emoji/HTML): puede cortar de más o mandar y recibir 400.
10. **Media** — `DIGEST_ERR` imprime 160 bytes de `$R`: un 401/proxy/HTML de error puede filtrar host, `chat_id` o restos del request.
11. **Media** — Env de chats no se les quita `\r`/espacios (sí al archivo): `chat_id` inválido → error opaco, o IDs distintos de los pensados.
12. **Media** — Sin retry ante 429/5xx ni distinción red vs API: un timeout transitorio deja `DIGEST_PARCIAL` y empuja a reenviar a mano.
13. **Baja** — Sin `flock`: dos corridas concurrentes mandan el mismo digest dos veces a ambos chats.
14. **Baja** — `message_id` por regex+`head -1`: si el texto ecoeado trae `"message_id": N`, el `mid` reportado puede ser el del digest, no el real.
15. **Baja** — `${1:?uso:…}` no usa el prefijo `ERR_*`; `ids:$ids` sale con espacio inicial; no se valida que los dos chats sean distintos.
