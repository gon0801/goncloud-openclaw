## Excepciones heredadas

Las once clases se mantienen o traducen explícitamente en SUA-02. Las decisiones
se validan contra estado, autoridad y criterio; el nombre antiguo de un verbo no
concede efectos ni convierte omisión en cumplimiento.

| Clase antigua | Tratamiento objetivo |
|---|---|
| SIN_REVISOR | Reintento/relevo elegible bajo presupuesto; sin reviewer no se aprueba código. |
| SIN_CUOTA | Espera o cuenta elegible; no compra ni amplía acceso. |
| AUTH_VENCIDA | Renovación autenticada y nueva comprobación; `listo` no fabrica credenciales. |
| CI_ROJO | Corregir/reintentar; `omitir` no permite merge ni acredita pruebas. |
| BOT_CALLADO | Consultar/reintentar el check requerido; silencio no es aprobación. |
| CONFIRMAR_PLAN | Sólo para alcance/autoridad pendiente; tamaño no exige confirmación. |
| NECESITA_DAVID | Acción fuera de autoridad vigente; agrupar una decisión concreta. |
| BLOQUEANTE_REPETIDO | Política vigente hasta adopción; después diagnóstico/límite finito, nunca cierre con bloqueante. |
| DEPLOY_FALLO | Consultar efecto antes de reintentar; `hecho` exige recibo y salud. |
| CIERRE_ROJO | Resolver evidencia faltante; respuesta humana no cambia tests rojos a verdes. |
| INESPERADO | Diagnóstico y decisión tipada; no poner contadores a cero por reintentar. |

## Fuera del reemplazo

U0–U3a, U1/sync, Fase14 y evidencia de encargos no se vuelven pendientes. Los
residuales nativos y de corte T1–T12 se integran en SUA-00/01/09 por perímetro.
No se sustituye la capacidad de diagnóstico de `summa-gate` ni los crons de
negocio. No hay replicación, failover entre hosts, frontend propio automático,
compra de modelos ni autorización de envíos/publicación por escribir este plan.
